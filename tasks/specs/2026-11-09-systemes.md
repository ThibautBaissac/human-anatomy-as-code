# Systèmes anatomiques

## Problem statement

Un étudiant qui révise l'appareil digestif ou le système nerveux ne peut pas l'isoler dans l'atlas. Le viewer filtre seulement par nature tissulaire (kind : os, muscles, artères…), et la donnée ne dit pas à quel système appartient une structure. La hiérarchie BodyParts3D contient bien des groupes « appareil digestif », « appareil respiratoire », etc. Mais 473 structures avec meshes n'ont pas de parent, et beaucoup d'organes sont rattachés à une région (tête, membres) plutôt qu'à un système. Les systèmes activables faisaient pourtant partie de la promesse du MVP.

## Solution

- **Dans la donnée.** Chaque structure porte un champ `systems` : la liste des systèmes auxquels elle appartient, pris dans un vocabulaire fermé de 12 systèmes. L'import le calcule, l'écrit dans le YAML en `draft`, et un curateur peut le corriger. Le compilateur le valide et le transmet à l'atlas.
- **Dans le viewer.** Un bloc « Afficher par système » montre ou masque chaque système présent dans le modèle. Un bouton « Isoler » par système ne montre que lui, et un bouton « Tout afficher » rétablit tout. Les systèmes masqués entrent dans l'URL.
- **Dans le panneau Info.** Les systèmes de la structure sélectionnée y sont affichés.

## User stories

1. As an étudiant, I want to hide a system (the digestive system), so that I can see what lies behind it.
2. As an étudiant, I want to isolate one system in one action, so that I can study it alone.
3. As an étudiant, I want a "show all" button, so that I get the whole body back after isolating a system.
4. As an étudiant, I want a structure that belongs to two systems (the pancreas: digestive and endocrine) to stay visible while one of them is shown, so that hiding the digestive system does not hide the endocrine pancreas.
5. As an étudiant, I want the system filter to combine with the kind filter, the dissection layers, the sections and ghost mode, so that I can, for example, look at the muscles of the respiratory system.
6. As an étudiant, I want structures with no system (body regions) to follow only the kind filter, so that they never disappear for no visible reason.
7. As an étudiant, I want only the systems present in the displayed model to be listed (the female model has no male genital organs; the male model has none of the HRA female organs), so that the list matches what I see.
8. As an étudiant, I want the Info panel to name the systems of the selected structure, so that I learn where it belongs.
9. As an étudiant, I want the hidden systems kept in the shared URL, so that a link shows the same view.
10. As an étudiant using a keyboard or a screen reader, I want every system control to be a native checkbox or button with an explicit name ("Isoler le système digestif"), so that I can use the filter without a mouse.
11. As an étudiant on a phone, I want the system filter in the Commandes tab, usable by touch, so that it works on mobile.
12. As a curator, I want each structure's systems written in its YAML file, so that I can review and correct them like any other field.
13. As a curator, I want an import to recompute the systems of draft structures and never touch reviewed ones, so that my corrections survive.
14. As a curator, I want to force the systems of a structure in the import overrides without reviewing the whole structure, so that I can fix a derivation mistake cheaply.
15. As a curator, I want the build to reject an unknown system name, so that a typo never reaches the viewer.
16. As a curator, I want the coverage report to count the structures with meshes that have no system, per kind, so that I know what to curate.
17. As a curator, I want the kidney, spleen and adrenal gland to be organs, not CNS, and the parts of the trapezius, the interspinales and the intertransversarii to be muscles, so that their systems and their colours are right.

## Implementation decisions

### Prerequisite: kinds

Some kinds are wrong because the keyword search walks up the is-a ancestors: `kidney`, `spleen` and `adrenal-gland` are `cns`; `ascending-part-of-trapezius`, `descending-part-of-trapezius`, `set-of-interspinales-cervicis`, `set-of-interspinales-lumborum`, `set-of-anterior-cervical-intertransversarii` and `set-of-posterior-cervical-intertransversarii` are `organ`. The fix comes first, in the import rules:

- a rule that keeps the kidney, the spleen and the adrenal (suprarenal) gland as `organ`, placed before the `cns` rule;
- muscle keywords: trapezius, interspinales, intertransversarii.

It gets tests and a re-import, and the decision goes into the data-model decisions file, as for the earlier kind fixes.

### Vocabulary

Twelve slugs, in this order in the interface (French name in `strings.ts`):

| Slug | French name | Covers |
|---|---|---|
| `skeletal` | Squelette et articulations | bones, cartilages, ligaments, joints |
| `muscular` | Système musculaire | muscles, tendons, fasciae |
| `cardiovascular` | Système cardiovasculaire | heart, arteries, veins |
| `lymphatic` | Système lymphatique | nodes, lymphatic vessels, spleen, thymus, tonsils |
| `nervous` | Système nerveux | brain, spinal cord, nerves |
| `sensory` | Organes des sens | eye and adnexa, ear, olfactory and taste organs |
| `respiratory` | Appareil respiratoire | nasal cavities, larynx, trachea, bronchi, lungs, pleura |
| `digestive` | Appareil digestif | mouth, teeth, tongue, salivary glands, pharynx, gut, liver, pancreas, peritoneum |
| `urinary` | Appareil urinaire | kidneys, ureters, bladder, urethra |
| `genital` | Appareil génital | male and female organs, mammary gland |
| `endocrine` | Système endocrinien | thyroid, parathyroids, adrenals, pituitary, pineal, endocrine pancreas |
| `integumentary` | Peau et phanères | skin, hair |

The mammary gland is in `genital` (teaching convention), and joints are in `skeletal`.

### Data: the `systems` field

- New optional structure field: `systems: [slug, …]`, unique items, from the 12 slugs. JSON Schema enum. An unknown value is a `schema` error.
- It is a computed field like `kind`:
  - the import recomputes it on draft structures and never changes it on reviewed ones (same rules as `kind`, `parent`, `regions` in `mergeDraft`);
  - it sits in the canonical key order right after `regions`;
  - an empty result writes no field.
- It is compiled into each model's atlas as is, sorted in vocabulary order.
- No inheritance at compile time: what the file says is what the atlas says.

### Derivation (import)

A pure function computes the systems of one structure from its kind, its English name and the slugs of its ancestors (parent chain in the plan). It takes the union of:

1. **Ancestors.** Each ancestor that is a system group of the BodyParts3D partonomy gives its system:
   - `alimentary-system` → `digestive`, `cardiovascular-system` and `vasculature-of-body` → `cardiovascular`, `respiratory-system` → `respiratory`, `nervous-system` → `nervous`, `urinary-system` → `urinary`, `genital-system` → `genital`, `endocrine-system` → `endocrine`, `integumentary-system` and `integument` → `integumentary`;
   - `musculoskeletal-system` and `deep-fascial-system` give nothing by themselves: rule 3 settles them.
2. **Name keywords.** A table of regular expressions per system, matched on the English name, in the style of the kind rules: kidney, ureter, bladder → `urinary`; lens, retina, cochlea → `sensory`; thyroid, adrenal → `endocrine`, etc. The code is the reference for the full table.
3. **The kind's system.**
   - Tissue kinds always add their system: bone, joint → `skeletal`; muscle, tendon, fascia → `muscular`; artery, vein → `cardiovascular`; lymphatic → `lymphatic`; nerve → `nervous`. That is how the diaphragm is `muscular` + `respiratory`.
   - `cns`, `skin`, `cartilage` and `ligament` add their system (`nervous`, `integumentary`, `skeletal`) only if rules 1 and 2 gave nothing. This rule was amended during implementation: a laryngeal cartilage is respiratory, and a ligament of the uterus is genital.
   - `organ` and `group` have no system by kind.
4. **Vessels and nerves stay in their own system.** For artery, vein, lymphatic and nerve, rules 1 and 2 do not apply: a gastric artery is `cardiovascular`, not `digestive`. Otherwise isolating the digestive system would show its vessels.

Other points:

- **Overrides.** `systems` in `bp3d-overrides.yaml` and `hra-overrides.yaml` (slug → list) replaces the derived result for that structure.
- **Female model.** The HRA import applies the same function to its structures (uterus → `genital`, female bladder → `urinary`, mammary glands → `genital`).
- **Expected result** on the current data (measured on a prototype): about 94 % of the instances with meshes get at least one system. The rest are regions (arm, foot, knee, wall of the chest…), which correctly have none.

### Coverage report

The `coverage` command gets a "sans système" column: structures with meshes and no system, per kind.

### Viewer

- **Catalog.** Each instance knows the systems of its structure (`systems: string[]`). The catalog lists the systems present among the instances shown in the model, in vocabulary order.
- **`ViewState.hiddenSystems: string[]`.** The default is empty.
- **`appearance`.** An instance with at least one system is hidden when all its systems are hidden. An instance with no system is not affected. The rule combines with the existing ones:
  - an instance out of the model or of a hidden kind stays hidden;
  - the selection stays visible, as today for hidden kinds;
  - ghosting (layers, crossing joints) applies to what remains visible.
- **Isolating a system** hides every other system present in the model. "Show all" empties `hiddenSystems`.
- **`view-hash`.** `sys=` lists the hidden systems, sorted; an unknown one is dropped, the rest applies. Existing URLs stay valid.
- **Picking.** A hidden instance is not pickable (already the case).

### Interface

- **"Afficher par système" block** in Commandes, after "Afficher par nature". It has:
  - one native checkbox per system present in the model;
  - next to it, a button with a short visible label and an explicit accessible name ("Isoler le système digestif");
  - a "Tout afficher" button.
- **Info panel.** A "Systèmes" line in the facts, with the names separated by commas, when the structure has some.
- **Strings.** All in French in `strings.ts`.

## Testing decisions

- **Seam 1: kind rules and the systems derivation function**, called with plain values (`kindOfName`, and the systems function with kind, name and ancestors):
  - the fixed kinds;
  - the three sources of the union;
  - vessels and nerves left out of organ systems;
  - `cns`/`skin` used only as a fallback;
  - regions without a system.
  - Prior art: `kind.test.ts`.
- **Seam 2: `importBp3d` and `importHra` on the existing fixtures:**
  - systems are written to the drafts;
  - a reviewed structure is left alone;
  - an override replaces the derived result;
  - a re-import is idempotent.
  - Prior art: `import-bp3d.test.ts`, `import-hra.test.ts`, `import-merge-safety.test.ts`.
- **Seam 3: `compileAtlas`:**
  - an unknown system is a `schema` error at its pointer;
  - `systems` compiled and sorted in vocabulary order;
  - the coverage column.
  - Prior art: `compile-rules.test.ts`, `coverage.test.ts`.
- **Seam 4: app pure modules:**
  - catalog: systems per instance, systems present;
  - `appearance`: all hidden → hidden, one shown → visible, no system → unaffected, selection visible;
  - `view-hash`: `sys=` round-trip and unknown values dropped.
  - Prior art: `catalog-appearance.test.ts`, `view-hash.test.ts`.
- **Seam 5: e2e:**
  - hiding the digestive system hides the liver and keeps the pancreas;
  - isolating the nervous system leaves no bone visible;
  - "Tout afficher";
  - the URL restores the filter;
  - the Info panel names the systems;
  - on phone, the block is in Commandes.
  - Prior art: `smoke.spec.ts`, `mobile.spec.ts`.

## Global constraints

- **Vocabulary.** Closed list of 12 slugs in English kebab-case, French names in the interface; the order of the table above is the display order and the compile order.
- **Data.** Computed values are `draft`; a reviewed structure is never modified; YAML keys follow the canonical order; the import stays idempotent.
- **Compatibility.** Existing URLs and atlases stay readable: `sys=` is optional and `systems` is optional.
- **Accessibility (RGAA 4.1.2).** Native controls, explicit accessible names, visible focus, 44 px targets on phone.
- **Performance.** Loading time unchanged (under 3 s on the e2e bench); applying a filter is a single appearance pass.
- **Dependencies.** No new dependency.

## Out of scope

- Wikidata "part of" (P361) as a fourth source.
- Trilingual system names in the data (the interface is in French only).
- A tree by system.
- Subsystems (upper and lower digestive tract, central and peripheral nervous system).
- Per-system colours: colour stays per kind.
- Systems on mesh-less structures computed from their descendants.

## Further notes

- The derivation prototype gave `pancreas` → digestive and endocrine, `diaphragm` → muscular and respiratory, `eyeball` → sensory, `tongue` → digestive, `heart` → cardiovascular. With the wrong kinds, `kidney` and `spleen` also came out as nervous, which is why the kind fix comes first.
- Brain structures of kind `organ` (corpus callosum, commissures) get `nervous` through their ancestors or the keywords, not through the kind.
